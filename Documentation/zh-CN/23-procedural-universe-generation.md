## 0. 核心原则（一句话）

> **固定世界规则 + 种子随机生成 + 约束验证 + 局部动态刷新。**

不要完全随机生成，也不必手工摆放整张宇宙。系统先生成符合「外缘出生 — 环带推进 — 中心高危」的**航网骨架**，再随机分配星域、势力、资源、异常和秘境，最后运行**验证器**；不合格则局部修正或重新生成。

**叙事对齐（`03`）：** 不同玩家看到相似的航网骨架，但因断航后的相位偏移，星域坐标、资源丰度、遗迹保存度、虫洞出口与势力边界并不完全相同——程序生成既是技术方案，也是**多位面世界观**的一部分。

## 1. 哪些固定，哪些随机

| 内容 | 建议 |
| --- | --- |
| 玩家出生在外缘 | **固定规则** |
| 宇宙中心及终局星域 | **固定位置**与叙事功能 |
| 外缘 → 开拓带 → 断航带 → 内环 → 中枢 | **固定层级**（环带） |
| 每层大致难度范围 | **固定规则** |
| 主线必须能抵达中心 | **固定规则** |
| 主线必需资源不会完全缺失 | **固定规则** |
| 星域数量、具体坐标 | **随机** |
| 星域间连接关系 | **约束随机** |
| 星球数量和类型 | **随机** |
| 势力控制范围 | **约束随机** |
| 资源丰度 | **带玩家比较优势的随机** |
| 虫洞、遗迹、秘境位置 | **条件随机** |
| 随机事件和临时异常 | **游戏过程中动态生成** |

**核心叙事节点**（中枢、主线必经锚点、终局秘境槽位等）可手工设计；其**坐标、邻接关系与周围填充内容**允许随种子变化。

## 2. 推荐生成流程

### 2.1 阶段 1：确定地图种子

每个玩家或位面获得一个**确定性种子**：

```text
UniverseSeed = Hash(服务器种子 + 玩家位面ID + 赛季ID)
```

同一 seed 每次加载地图相同，便于：

- 存档与读档；
- 调试与 Bug 重现；
- 分享地图种子；
- 服务器验证（Online）；
- 赛季重置。

**不要**依赖保存整个随机过程；只保存 **seed** 与玩家后来造成的状态变化（通航 tier、探索度、修复记录等）。详见 `06-data-and-save.md` §4.3.7。

---

### 2.2 阶段 2：生成宇宙环带

先确定**中心坐标**，再生成若干距离层。环带不是绝对同心圆，而是带熵雾扭曲的不规则区域——视觉上可像被撕裂的蛛网，避免过于人工。

| 环带 | 距中心距离 | 推荐难度 |
| --- | ---: | ---: |
| 外缘带 | 80–100% | 1–15 |
| 开拓带 | 60–80% | 10–30 |
| 断航带 | 40–60% | 25–50 |
| 位面带 | 20–40% | 45–75 |
| 内环带 | 5–20% | 70–95 |
| 群星中枢 | 0–5% | 终局 |

与 `20` §6 环带表一致；本文补充**距离带数值**与生成顺序。

---

### 2.3 阶段 3：生成航网节点

每个环带生成一定数量的**星域节点**。节点数据结构（与 `20` §14 对齐并扩展）：

```text
Sector
├─ id
├─ coordinate
├─ ring
├─ nodeType
├─ baseDifficulty
├─ faction
├─ environment
├─ resourceProfile
├─ planets[]
└─ specialTags[]
```

**首版规模建议（MVP 验证后可扩大）：**

| 类型 | 数量 |
| --- | ---: |
| 外缘出生星域 | 1 |
| 普通星域 | 25–35 |
| 势力核心星域 | 4–6 |
| 资源特化星域 | 6–10 |
| 遗迹星域 | 3–5 |
| 熵雾高危星域 | 4–8 |
| 特殊星域 | 2–4 |
| 中枢星域 | 1 |

地图最终规模可扩大；**M3 验证版**建议控制在 **30–50 个星域**，星域内部再生成星球与兴趣点（见 §6）。

---

### 2.4 阶段 4：连接为网状结构

**禁止**任意两节点随机连线。推荐三步法：

#### 1）保证基础可达

先生成一棵从**外缘通向中心**的最小连通网络，确保所有关键节点可达。

#### 2）增加环带横向连接

同一环带的邻近星域之间增加航线，让玩家可以**横向发展**，而不是只往中心走。

#### 3）增加少量捷径和危险连接

- 虫洞；
- 熵雾捷径；
- 单向航道；
- 隐藏航线；
- 位面裂隙。

每个普通节点建议连接 **2–4 条**航线。连接太少会退化成关卡树，太多则路线选择失去意义。

#### 拓扑必须检查的规则

- 出生点不能只有一条出口；
- 前两个环带至少各有两条推进路线；
- 任意关键节点不能因单条航线断开而永久不可达；
- 通往中心至少有两条总体路线；
- 捷径不能让玩家直接跳过整个成长阶段；
- 虫洞出口不能落入无法返航且必死的区域。

与 `20` §1.3「禁止线性关卡树」及 §9 虫洞边规则一致。

## 3. 难度如何生成

不能只根据欧氏距离计算难度，否则两个坐标很近的节点可能实际上要绕很远。

**建议综合公式：**

```text
Difficulty =
  RingBase
+ RouteDepth × 2
+ EntropyLevel × 3
+ FactionModifier
+ Random(-3, +3)
```

其中：

- `RingBase`：环带基础难度（§2.2）；
- `RouteDepth`：从**出生点**的最短航路深度（非直线距离）；
- `EntropyLevel`：熵雾强度；
- `FactionModifier`：势力危险修正；
- `Random`：小幅波动，须由 seed 驱动。

**硬边界：**

- 外缘普通节点不能生成终局难度；
- 相邻普通节点难度跳跃不能超过阈值（建议 ≤8，可配置）；
- 高难节点允许提前出现，但必须可以绕行；
- 玩家进入下一环带前，至少应能获得对应舰船模块（与 `13` 舰船门、`20` §4 软门配合）。

**表现：** 不要只显示「推荐战力 5000」，还应说明难在哪里——敌人强度、熵雾侵蚀、航行距离、补给压力、扫描干扰、特殊战斗机制（对齐 `20` §4 五维）。

## 4. 势力分布如何生成

势力不应逐节点随机，否则地图会像马赛克。应先生成**势力核心**，再向相邻节点扩张。

### 4.1 生成步骤

1. 为每个势力选取 1–2 个核心星域；
2. 核心之间保持最低距离；
3. 根据航网距离向周围扩散影响力；
4. 在接壤处生成争夺区；
5. 在熵雾深处保留中立、失控或未知区域。

### 4.2 势力倾向（示例）

| 势力 | 倾向位置 | 常见节点 |
| --- | --- | --- |
| 边境卫队 | 外缘与稳定航线 | 前哨、航标、军事站 |
| 裂隙商盟 | 断航带、虫洞附近 | 黑市、回收站、秘密航线 |
| 古代机械 | 遗迹和中枢方向 | 废墟、封锁节点、守卫设施 |
| 熵雾异变体 | 高熵雾区域 | 生物星球、污染区 |
| 中立殖民地 | 安全资源区 | 城市、订单、贸易站 |

势力边界不需要完全排他。每个星域可记录：

```text
控制势力：边境卫队
影响势力：裂隙商盟 35%
冲突状态：走私活动
```

细则与任务挂钩见 `21`；本文管**生成时的空间分布**。

## 5. 资源产出如何生成

资源须同时满足：

1. 每位玩家都能独立完成基础主线；
2. 不同位面形成**比较优势**（对齐 `20` §7、`18` 位面偏置）；
3. 不会因随机结果永久卡死。

### 5.1 基础保障资源

出生区域必须拥有：

- 基础金属；
- 基础能源；
- 基础维修材料；
- 第一阶段舰船升级材料；
- 第一条生产链所需材料。

这些可以**丰度不同**，但不能**缺失**。

### 5.2 位面优势资源

初始化时随机选择一种**主优势**和一种**次优势**，并配一个**缺口**：

```text
主优势：金属产量 +40%
次优势：遗迹蓝图出现率 +20%
缺口：生物材料产量 -25%
```

所有玩家都有优势和短板，而不是随机分出「好地图」和「坏地图」。

### 5.3 稀有资源

稀有资源根据星域标签生成，例如：

| 区域标签 | 稀有倾向 |
| --- | --- |
| 高熵雾区 | 相位晶体 |
| 机械遗迹 | 古代部件 |
| 生物星域 | 生物纤维 |
| 恒星异常 | 高密度能源 |
| 虫洞附近 | 稳定介质 |

主线需要的稀有资源应至少有**三种获得方式**：

- 本地低效率生产；
- 探索特定星域；
- 市场交易（`16`）。

## 6. 星域内部如何生成星球

星域内部不需要完全模拟真实天文学，但要有**合理模板**：

```text
星域模板
├─ 矿业星系
├─ 工业废墟星系
├─ 殖民星系
├─ 生物异常星系
├─ 熵雾裂隙星系
├─ 中转站星系
└─ 古代航网星系
```

**矿业星域示例规则：**

- 1 颗恒星；
- 2–5 颗行星；
- 至少 1 颗矿业行星；
- 1–3 个小行星带；
- 可能出现废弃采矿站；
- 较低概率出现遗迹；
- 商盟或卫队出现概率提高。

星球内部资源受星域主题影响，但保留一定随机性。  
**现况：** 第七前沿为手工模板（`17`）；M3+ 域内节点可接本文模板 + seed。

## 7. 特殊星域如何放置

特殊星域不能普通随机抽中后随便放置，需要**单独放置规则**。

| 特殊区域 | 放置约束 |
| --- | --- |
| 初始前哨 | 出生点 |
| 势力首都 | 与其他首都保持距离 |
| 古代巨构 | 中环以后 |
| 位面中转站 | 多条航线交汇处 |
| 中枢封锁区 | 中心附近 |
| 超级矿区 | 危险区或路线末端 |
| 战争遗迹 | 两大势力交界 |
| 孤立殖民地 | 熵雾断路后方 |
| 大型虫洞 | 距离较远的两个区域之间 |
| 前任舰长遗迹 | 主线可达但非必经 |

**条件匹配**（非纯随机坐标）：

```text
寻找满足条件的节点：
  环带 = 断航带
  熵雾等级 >= 3
  距离出生点 >= 8
  至少有 2 条连接
  不是主线必经节点
→ 从候选集中按 seed 随机选取
```

## 8. 秘境生成方式

秘境**不建议**全部在初始化时生成实体节点。

更合适的方式：

- 初始化时生成「**秘境槽位**」；
- 玩家满足条件后才确定具体内容；
- 部分秘境按时间动态出现；
- 入口坐标可以漂移；
- 内容由秘境种子固定。

**示例：**

```text
秘境槽位：
  位于断航带
  关联古代机械主题
  需要扫描 Lv.3
  在玩家取得第二段航网日志后激活
```

激活时生成：入口坐标、内部地图、敌人组合、特殊规则、奖励、有效期。

### 8.1 秘境分类

| 类型 | 初始化方式 |
| --- | --- |
| 主线秘境 | 预留位置，剧情触发 |
| 一次性遗迹 | 初始化生成 |
| 随机裂隙 | 动态生成 |
| 玩家共享秘境 | 服务器生成（Online） |
| 位面专属秘境 | 玩家地图 seed 生成 |
| 虫洞秘境 | 虫洞事件触发 |

与 `20` §9 虫洞边、`21` §6.3 探索度 >100% 事件池衔接。

## 9. 生成后必须运行验证器

程序生成地图后**不能直接**交给玩家，必须进行自动验收。

### 9.1 可达性验证

- 出生点能否抵达所有主线节点；
- 能否最终抵达中心；
- 至少有两条中长期路线；
- 有没有孤立但未标记为秘境的节点；
- 虫洞是否造成死路。

### 9.2 经济验证

- 第一条生产链能否完成；
- 每阶段舰船升级材料是否可获得；
- 基础维修是否可持续；
- 主线资源有没有完全缺失；
- 位面优势是否过强或过弱。

### 9.3 难度验证

- 新手相邻节点是否存在可攻略目标；
- 是否出现无法绕过的难度断层；
- 高价值节点是否完全无风险；
- 进入下一环带前能否获得必要模块。

### 9.4 内容验证

- 每个环带是否存在至少一种新敌人 / 资源 / 机制；
- 势力核心是否过度集中；
- 特殊星域是否发生位置冲突；
- 秘境是否全部堆积在一个区域。

### 9.5 修复策略

不合格时**优先局部修复**：

```text
缺铁矿     → 调整一个外缘节点资源
主线断路   → 增加航线
难度断层   → 降低守门节点难度
势力重叠   → 移动势力核心
```

只有无法修复时才**重新生成整张图**（换 seed 或局部重掷）。

## 10. 数据层结构（与 `20` §14 对齐）

```text
Universe
├─ seed
├─ centerCoordinate
├─ planeModifiers          // 主/次优势与缺口
├─ factionSeeds
├─ sectors[]
├─ routes[]
├─ specialSlots[]          // 秘境槽位
└─ validationResult

Sector
├─ id, coordinate, ring
├─ difficulty
├─ faction, environment
├─ resourceProfile
├─ planets[]
├─ specialTags[]
└─ discoveryState          // 五种航网状态，见 20 §3

Route
├─ from, to
├─ type                    // Lane | Wormhole | …
├─ entropy, stability
├─ travelCost, requirements
└─ discoveryState
```

**星域与航线分开存储**：「修复断航」改变的通常是**连接线状态**，而不是星域本身坐标。

## 11. 初始化伪代码

```csharp
GenerateUniverse(seed)
{
    rng = new SeededRandom(seed);

    rings = GenerateRings(rng);
    sectors = PlaceSectors(rings, rng);

    routes = BuildMinimumConnectedNetwork(sectors);
    AddLateralRoutes(routes, sectors, rng);
    AddRiskyShortcuts(routes, sectors, rng);

    AssignDifficulty(sectors, routes, rng);
    AssignFactionCores(sectors, rng);
    ExpandFactionInfluence(sectors, routes, rng);

    AssignPlaneAdvantages(rng);
    AssignResources(sectors, rng);
    GeneratePlanets(sectors, rng);

    PlaceRequiredLandmarks(sectors, routes, rng);
    ReserveSecretRealmSlots(sectors, rng);
    PlaceWormholes(sectors, routes, rng);

    result = ValidateUniverse();

    if (!result.IsValid)
        RepairOrRegenerate(result);

    return universe;
}
```

实现归属建议：`UniverseGenerator`（纯生成 + 验证）+ `GridService`（运行时状态与存档同步）。

## 12. 最适合当前项目的实现范围

首个版本**不必**生成完整宇宙。建议先验证**小型随机航网**：

| 项 | 验证版目标 |
| --- | --- |
| 星域数 | 15–20 |
| 环带 | 4 |
| 域内节点 | 每星域 3–6 |
| 势力 | 2 |
| 资源倾向 | 3 |
| 特殊星域 | 2 |
| 主线秘境 | 1（固定槽位） |
| 动态秘境 | 1 |
| 虫洞捷径 | 1 |
| 通往终局路线 | ≥2 |

**第七前沿（`17`）** 在 M2 阶段保持**手工内容**；M3 起可用上述规模做**第二个星域**或**同 seed 的宇宙层试点**，不与新手主链冲突。

## 14. 设计验收标准

- 同一 seed 两次生成结果一致（确定性）。  
- 验证器能拦截「主线断路 / 资源缺失 / 难度断层」类坏图。  
- 出生扇区满足 §5.1 基础保障 + §5.2 比较优势，无劣等宇宙。  
- 至少两条中长期路线抵达中枢方向。  
- 局部修复优先于整图重掷。  
- 随机差异可叙事解释为相位偏移（`03`），而非纯数值抽奖。
